# 阶段 3：交互体验与细节打磨

> 前置：阶段 2 验收通过。新会话先读三个配置文件，再读本文件。

## 阶段目标
完成所有增强交互，做响应式适配，把细节打磨到可交付状态。

## 具体任务

1. **文章目录导航 `PostToc.vue`**
   - 解析正文 blocks 中的 heading1 / heading2 / heading3，自动生成目录树
   - 桌面端：详情页右侧悬浮固定，宽约 240px
   - 滚动时 IntersectionObserver 高亮当前章节
   - 点击目录项平滑滚动到对应锚点
   - 移动端：折叠为顶部下拉/悬浮按钮，不占正文空间

2. **全局交互**
   - 全站 `scroll-behavior: smooth`
   - 所有可点击元素统一 hover 过渡（200ms ease-out）
   - 返回顶部按钮：滚动超过一屏后淡入，固定右下角

3. **详情页增强**
   - 文末「上一篇 / 下一篇」导航（按发布日期相邻）
   - 阅读时长由 `utils.ts` 根据正文中文字符数自动估算（≈400 字/分钟）

4. **响应式适配**
   - 断点：移动端 < 768px / 平板 768–1024px / 桌面 > 1024px
   - 移动端：卡片单列，导航栏折叠为汉堡或精简链接，目录改为浮层
   - 平板：卡片双列
   - 桌面：卡片三列
   - 正文区在移动端保留舒适行宽

5. **细节体验**
   - 页面入场：淡入 + 轻微上移，300ms
   - 文章封面图：`loading="lazy"` + 淡入占位
   - 空状态：无文章 / 无分类时显示优雅的空提示，不要白屏
   - 404 页面：风格化「圣夜迷途」提示

## 输出要求
- 所有交互正常，无控制台报错
- 手机、平板、桌面三端布局都可读
- 动效克制，不干扰阅读

## 验收标准
1. 目录跟随高亮准确，点击跳转定位正确
2. 主题切换、平滑滚动、返回顶部、上一篇/下一篇全部可用
3. 以 375px（iPhone SE）、768px（iPad）、1440px 三档宽度检查，无横向滚动、无内容重叠
4. 移动端目录不遮挡正文
5. Lighthouse 移动版性能分 ≥ 90，可访问性 ≥ 90
